# iClass: a SchoolSims Player

An interactive bilingual simulation platform for leadership training. Learners navigate a realistic workplace scenario across 7 slides — from context and video to a branching decision — in **English or Spanish**, with **5 selectable character ethnicities**. Designed for colleges and corporate L&D teams.

## Features

- **7-slide branching scenario** — context, text+image, video, decision (A/B), outcome, summary
- **Bilingual** — English and Spanish; content and UI fully localized
- **5 character ethnicities** — African, Caucasian, East Asian, Latin, South Asian (photo + video only; no effect on scenario text or outcomes)
- **Text-to-speech** — optional ElevenLabs integration with file-based caching; falls back silently when no key is set
- **Post-simulation review** — star rating + open feedback form, stored server-side
- **Keyboard shortcuts** — press `[A]` or `[B]` on the decision slide

## Scenario Flow

```
Setup → 1 Context → 2 Text+Image → 3 Video → 4 Decision → 5A/5B Outcome → 6 Summary → Restart
```

- **Language** (`lang`): `en` or `es` — localizes all text, UI labels, and video
- **Ethnicity** (`ethnicity`): `african`, `caucasian`, `east_asian`, `latin`, `south_asian` — changes character photo and video only; no effect on scenario text, role, or outcomes
- **Decision**: Option A commits to the deadline; Option B proposes a phased pilot. The summary reflects whichever path was chosen.

## Characters (personas)

Each on-screen character is defined in `backend/personas.json`: a name per language (in that language's script), a photo (with optional per-language overrides), a video per language, and the languages it is suggested for. Choosing a language pre-selects its suggested character; the learner can still pick another. Scenario text uses the placeholder name `Jordan Chen`, which is swapped for the chosen character's name everywhere it appears.

**Regional variants.** A locale can be a language (`es`) or a regional variant (`es-AR`, `sw-TZ`, `ar-JO`). Anything missing for a variant falls back to its base language, then English: character names, photos, videos, captions and narration. So `es-AR` plays the Spanish videos, but can give the character an Argentine name (`"es-AR": "Martín Pereyra"` in personas.json). Included (20): English (International master / US / UK), Spanish (generic / Spain / Mexico / Argentina / Chile), Portuguese (Portugal), Basque, Afrikaans, Chinese (Mandarin, Simplified / Cantonese, Hong Kong, Traditional), Swahili (Kenya / Tanzania), Arabic (UAE / Jordan), Hebrew (Israel), Urdu (Pakistan) and Nepali (Nepal). Arabic, Hebrew and Urdu lay out right-to-left. All regional text was written by AI and still needs a native-speaker review.

To add a locally styled photo or video, drop the file in `public/assets/` and point the persona at it — no code changes needed.

## Locale studio (AI-drafted, human-approved localizations)

Open **/admin** (dev server: `http://localhost:5173/admin.html`). From there you can:

1. **Draft a locale**: give a language code (`pt-BR`), its name and the setting ("Campinas, Brazil — private university"). Claude rewrites the English story for that place (institution, currency, calendar) while keeping the same decision, outcomes and the video's line ("Can we commit to four weeks?"). For an existing language, **Re-localize** rewrites only the story and keeps the reviewed UI wording.
2. **Review** every field next to the English master and an English back-translation, with notes on facts to check. Edit anything inline.
3. **Approve & publish**: the locale is merged into `backend/scenario.json` and appears for learners. Pending drafts (`backend/drafts/`, git-ignored) are never shown to learners.

Safety rails: the model only writes text; ids, branching and outcome directions are rebuilt from the English master, so a draft cannot break the scenario. Approval is blocked if a field is empty or the character-name placeholder is missing. A brand-new language plays the English videos with localized on-screen text until videos are recorded for it.

Setup: put `ANTHROPIC_API_KEY=...` in `.env.local` at the repo root (optional: `ANTHROPIC_MODEL`, default `claude-sonnet-5-5`). Drafting and approving write files, so they run in a local copy or a Codespace; commit `backend/scenario.json` and redeploy to publish to the hosted site. On a hosted site the admin page requires `ADMIN_TOKEN`.

## Localized character videos (HeyGen)

`scripts/make_videos.py` makes each version's video with HeyGen: the character speaks the lines in that language and accent, in front of a region-appropriate background, with matching subtitles. The list of clips (character, lines, voice, background) is in `scripts/heygen/clips.json`; background image briefs are in `scripts/heygen/BACKGROUNDS.md`.

1. Put `HEYGEN_API_KEY=...` in `.env.local` (repo root).
2. Optional: add background images to `scripts/heygen/backgrounds/<locale>.jpg` (without one, the character keeps its photo's background).
3. `python scripts/make_videos.py --check` (key + credits), then `--dry-run` (what would be made, which voice; spends nothing).
4. `python scripts/make_videos.py --only es-AR` to make and review one clip, then run without `--only` for the rest.
5. Commit `public/assets`, `backend/personas.json` and push.

Use `--list-voices Spanish` to browse voices and set `voice_id` in clips.json to force one. Existing clips are skipped unless `--force`.

## Deploying to Vercel

Import the repo in Vercel (framework: Vite). `vercel.json` builds the frontend and runs the FastAPI backend from `api/index.py` as a serverless function. Optional: set `ELEVEN_LABS_API_KEY` in the project's environment variables for narration. On Vercel, submitted reviews are written to the function logs (search for `REVIEW`), and scenario editing via the API is disabled.

## Scenario Content

All slide content lives in `backend/scenario.json` as a linked graph keyed by language:

```json
{
  "start_node_id": "context",
  "en": { "nodes": { "context": {...}, "decision": {...}, ... }, "ui": {...} },
  "es": { "nodes": { ... }, "ui": {...} }
}
```

Edit content via `POST /api/scenario/{lang}`, or directly in the JSON file (restart server to reload).
